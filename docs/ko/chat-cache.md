# 모든 채팅을 기본 캐시 (`v1.17.0-datalite.5`)

기존 채팅 캐시는 메시지가 40개 이상인 채팅만, 최근 24개까지 보관했습니다.
짧은 채팅도 반복 접속하면 다시 받아야 하고, 메시지 수가 적어도 플러그인 부가
데이터가 클 수 있으므로 데이터 절감 목적에 맞게 두 제한을 제거했습니다.

## 기본 동작

- 열어서 받은 완전한 채팅은 메시지 수·용량과 관계없이 브라우저의 IndexedDB에
  캐시합니다. 메시지가 없는 채팅도 메모 등 부가 데이터를 포함해 보관합니다.
- 서버 저장이 성공한 채팅도 저장 요청에 사용한 동일한 사본으로 캐시를 갱신합니다.
  저장 중 스트리밍이나 UI 편집이 계속돼도 아직 전송하지 않은 내용은 사본에 넣지
  않습니다. 차분 저장 실패 후 전체 저장으로 재시도할 때도 같은 스냅샷을 사용합니다.
- 저장에 실패하면 이전 사본을 유지합니다. 로컬 사본 저장 실패는 성공한 서버
  저장을 실패로 바꾸지 않습니다.
- 서버에 있는 모든 채팅을 미리 다운로드하지는 않습니다. 실제로 열거나 저장한
  채팅부터 사본이 생깁니다. 첫 접속·새 브라우저·캐시 삭제 후에는 본문 전송이 필요합니다.

## 저장 공간과 호환성

채팅 캐시는 기존 `pocketrisu-chat-copies` IndexedDB와 같은 스키마를 사용하므로
업데이트 전의 사본도 재사용합니다. 개수·최소 크기로 캐시 대상을 거르지 않고,
브라우저가 `QuotaExceededError`를 반환할 때 오래 사용하지 않은 다른 사본을
최대 8개씩 정리해 재시도합니다. 정리에는 키와 사용 시각만 읽으며 모든 채팅
본문을 한꺼번에 메모리에 올리지 않습니다. 서버 원본은 이 정리의 대상이 아닙니다.
다른 사본을 정리해도 저장할 수 없으면 캐시 없이 기존 네트워크 경로로 동작합니다.

채팅 사본은 접속 단말의 저장 공간을 사용합니다. 서버 RAM에 전체 사본을 추가로
쌓는 방식이 아닙니다. 브라우저 정책에 따라 로컬 사본이 삭제되거나 저장이 거부될
수 있습니다. 메인 DB·플러그인 전송 캐시의 별도 512MiB 한도는 유지합니다.

## 이번 변경의 전송량 범위

다시 열 때 기존 메시지 prefix 검증을 계속 수행합니다. 서버의 메시지가 다르면
기존 전체 읽기로 복구하므로 캐시 사본을 최신본으로 무조건 신뢰하지 않습니다.
자신이 저장한 메시지도 다음 접속의 prefix 기준에 포함되어 중복 수신을 줄입니다.

이번 변경은 채팅의 전체 revision/304 확인을 추가하지 않습니다. 메시지 외의 메모·
로어북·플러그인 필드는 기존 응답에 포함되고, 메시지가 없는 사본은 기존 서버
프로토콜에 맞춰 전체 읽기를 사용합니다. 따라서 모든 채팅을 캐시해도 앱 전체
트래픽이 버전값 몇 바이트만으로 줄어드는 것은 아닙니다.
