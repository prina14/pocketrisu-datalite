# 저장 기준 초기화·서버 응답 복사 최적화

v1.17.0-datalite.12에 포함된 변경입니다.

사용자 측정의 저장 기준 초기화 약 210ms와 서버 인코딩 약 174ms를 대상으로 합니다.
이후 UI 프레임까지 남은 약 300ms를 특정 함수나 렌더링 비용으로 단정하지 않습니다.

## 저장 기준 초기화

정규화된 독립 snapshot과 프로토콜 해시는 기존처럼 초기화 때 준비합니다. 저장 감시의 설치나
필수 데이터 검증을 뒤로 미루지 않습니다. 변경 비교용 보조 JSON 문자열·UTF-8 크기만 처음
조회할 때 계산하며, 원본은 사용 중인 DB가 아닌 소유한 정규화 snapshot을 참조합니다.
사용자가 첫 저장 전에 바꾼 내용이 새 비교 기준으로 섞이지 않습니다.

크기 추정은 필요한 대기 항목을 모두 계산해 기존 값을 유지합니다. 모듈은 항목별 해시를 한 번
계산해 배열 해시를 합성하므로 같은 모듈을 두 번 해시하지 않습니다. 중복·잘못된 모듈 ID도
원래 배열 순서의 항목 해시로 계산합니다. 서버에서 따로 관리하는 pluginCustomStorage는 기존처럼
빈 객체로 고정하되, 버릴 과거 값을 해시하기 전에 고정합니다.

실제 Chromium에서 약 10MB 문자열을 포함한 합성 데이터로 v11 소스와 수정 소스를 비교했습니다.
워밍업 1회 뒤 5회 중앙값은 초기화 **45.4 → 18.3ms**, 첫 저장 **9.4 → 23.7ms**였습니다.
첫 저장 또는 최초 크기 조회로 일부 계산이 이동하는 절충이 있습니다. 패치·예상 해시·저장 후
해시·추정 크기는 두 구현에서 일치했습니다. 관련 없는 앱 의존성을 대체한 모듈 하네스이며
전체 앱이나 사용자 환경의 실제 개선율은 아닙니다.

## 서버 인코딩·복사

HTTP DB 읽기에는 독립된 Buffer를 한 번 할당하고 헤더·인코딩 데이터를 모두 채우는 전용
encoder를 사용합니다. 기존 Uint8Array에 전체 데이터를 복사한 뒤 다시 Buffer로 복사하던
단계를 줄입니다. 기존 공개 legacy encoder의 타입·압축 방식과 백업 경로는 유지합니다.
결과가 인코더의 재사용 영역을 참조하지 않아 후속 인코딩으로 응답 내용이 변하지 않습니다.

delta 패킷도 이미 소유한 출력 배열의 Buffer view로 전송합니다. 이후 압축 중에도 해당 배열이
유지되며, 별도의 패킷 전체 복사를 하지 않습니다. 새로운 대형 DB 캐시는 추가하지 않습니다.
MessagePack 인코딩·해시 비용 자체는 남으므로 사용자 서버의 174ms 전체가 없어지는 변경은 아닙니다.

## 확인

- 초기 JSON 생성 지연, 첫 수정·삭제·모듈 변경, 첫 크기 조회와 후속 저장의 정확성 검증.
- 중복 모듈 ID를 포함한 초기 해시가 프로토콜 해시와 일치하는지 검증.
- 서버 출력의 기존 framing·바이트 일치와 후속 대형 인코딩 이후 내용 보존 검증.
- 실제 Chromium에서 초기화·첫 저장·크기 추정과 기존 구현 결과 비교.
- 초기 검증 시 앱 1,823개·서버 252개·호환성 154개 통과. 타입 오류 0개, 기존 접근성 경고 4개.
