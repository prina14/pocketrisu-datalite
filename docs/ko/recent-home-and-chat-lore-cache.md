# 최근 대화 위치 고정과 반복 대화 응답 축소 — 배포 전 검증

2026-11-13, 현재 서버 DataLite 28을 기준으로 확인했다. 이 문서의 변경은 로컬 소스에만 반영됐으며 프로덕션 빌드·배포는 아직 실행하지 않았다.

## 첫 화면 배치

- 홈 제목을 언어 설정과 무관하게 `Recent Chats`로 표시한다. 사이드바의 언어 설정은 유지한다.
- 최초 HTML, 로딩 미리보기, 실제 데스크톱·모바일 최근 영역에 같은 182px 높이를 사용한다. 카드가 아직 없을 때도 공간을 유지하므로 활동 기록을 받은 뒤 카드를 채워도 아래 영역이 밀리지 않는다.
- 최근 대화 숨김 설정은 기존 설정을 따르며, 이름이나 대화 내용 없이 표시 여부만 기존 로컬 외형 캐시에 보관해 다음 로딩 화면에도 반영한다.
- 실제 Chrome 개발 화면에서 1440px·390px 너비로 최초 로딩 셸 → 빈 최근 영역 → 카드 3개 → 접속 통계 반영을 비교했다. 모든 단계에서 Recently Uploaded 위치 변화 0px, 가로 넘침 없음, 런타임 오류 없음이었다.

## `0 / fetch / nodeStorage.ts` 요청

사용자가 제시한 요청 이름은 대화 인덱스 0을 읽는 `/api/chat-content/[character]/0` 요청과 부합한다. 실제 최근 캐릭터 세 개를 각각 반복해서 열어 확인했다. 첫 캐릭터의 기존 메시지 155개, 둘째 캐릭터의 메시지 318개 이후 추가 메시지 등에 대해 서버의 변경분 응답이 작동했다. 하지만 기존 방식은 메시지만 생략하고 로어북(`localLore`) 등 다른 필드는 매번 응답에 넣었다.

예를 들어 메시지 추가가 전혀 없는 응답에 로어북 JSON 약 1.10MB 또는 1.07MB가 포함됐다. 전송 압축 후에는 약 67.4kB·51.1kB였다. 일부 반복 요청은 HTTP 캐시 검증만 수행해 실제 네트워크 전송이 수백 바이트였으므로 개발자 도구의 리소스 크기와 실제 전송량을 구분해야 한다. 사용자가 본 507kB 항목이 정확히 어떤 캐릭터·어떤 응답 상태였는지는 이 숫자만으로 확정하지 않았다.

## 수정 방법

- 브라우저가 보관한 로어북의 지문을 요청에 함께 보내고, 서버가 메시지 접두부와 로어북 지문을 모두 확인한 경우에만 로어북을 생략한다.
- 메시지·로어북 변경 또는 캐시 없음은 기존 전체 응답 경로를 사용한다. 메모·스크립트 상태 등 다른 필드는 계속 최신 값으로 받는다.
- 메시지가 0개인 인사말 전용 대화도 읽기 경로에서 빈 접두부를 검증해 로어북을 재사용할 수 있다. 쓰기 프로토콜과 DB 데이터는 변경하지 않는다.
- 로어북 내부의 명시적 null은 생략된 속성과 구분한다. 기존 서버·기존 클라이언트와의 응답 호환성을 유지한다.

실제 브라우저 사본의 메타데이터를 메모리에서만 사용해 실제 응답 함수와 같은 Brotli 품질 4로 비교했다. 서버 데이터나 사용자 설정을 수정하지 않았다.

| --- | ---: | ---: | ---: | ---: |
| 큰 로어북 A | 1,026,730B | 4,474B | 67,382B | 2,046B |
| 큰 로어북 B | 997,454B | 5,174B | 51,079B | 2,003B |

이는 동일한 로어북을 다시 보내는 비용의 비교이며, 모든 507kB 요청이 약 2kB가 된다는 보장은 아니다. 로어북 이외의 큰 상태·메모리 데이터는 이번 변경에서도 전송될 수 있고, 실제 서버에 적용한 뒤 다시 측정해야 한다.

관련 테스트에서 변경된 로어북·명시적 삭제·빈 대화·구버전 서버·최신 스크립트 변수 유지와 서버 원본 비변경을 확인했다. 타입 검사 오류 0개, 기존 접근성 경고 4개였다. 비밀번호·토큰·대화 본문·이미지 URL은 이 문서와 크기 측정 결과에 포함하지 않았다.
