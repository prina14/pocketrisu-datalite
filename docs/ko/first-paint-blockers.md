# 첫 화면의 외부 CSS 대기 제거

기준은 `v1.17.0-datalite.7`이며 아래 수정을 `v1.17.0-datalite.8`에 포함합니다.
후속 빌드·배포 요청에 따라 프로덕션 빌드와 GitHub Release 검증을 진행합니다.

## 확인한 병목

기존 `index.html`은 본문 표시 전에 jsDelivr의 KaTeX CSS와 Google Fonts CSS를 읽습니다.
이 stylesheet 요청은 첫 페인트와 module script 실행을 지연시킬 수 있습니다.
문서가 작고 PC의 CPU가 빨라도 외부 응답을 기다리는 시간은 남습니다.

v7의 빌드된 HTML에 직접 연결된 JavaScript는 53개, 비압축 약 4.75 MB,
동일 파일을 gzip으로 압축한 합계는 약 1.30 MB였습니다. 동적 요청·캐시·HTTP 헤더를
포함한 실사용 전송량은 아닙니다. 따라서 화면의 텍스트 양만으로 준비 비용을 판단하기 어렵습니다.

## 제어 실험

v7의 **동일한 프로덕션 JavaScript**와 실제 Node 서버·빈 테스트 DB·Chromium을 사용했습니다.
브라우저 캐시는 비활성화했고 한 번 로그인한 뒤 비교해 암호 입력 시간을 제외했습니다.
외부 stylesheet 요청은 CDP에서 가로채 3초 뒤 빈 CSS로 응답해 실제 인터넷 없이 지연을 재현했습니다.
비교 조건은 임시 HTML에서 외부 CSS 링크 두 개만 제거한 것이며 제품 `dist/`는 수정하지 않았습니다.

| 조건 | 첫 콘텐츠 표시(FCP) | 데이터 로딩 완료 확인 |
| --- | ---: | ---: |
| 외부 CSS 3초 지연 | 3,144 ms | 3,354 ms |
| 외부 CSS 대기 제거 | 156 ms | 515 ms |

FCP는 최초 콘텐츠 표시이며 대화 준비 완료와 다릅니다. 데이터 로딩 완료는
`pocketrisu:startup:load-data` 측정의 완료를 폴링해 확인했으므로 약 200ms의 관측 오차가 있습니다.
이는 외부 CSS가 시작을 막을 수 있다는 제어 실험이지, 수정본을 빌드한 성능 비교나
사용자 Android·Oracle 서버의 개선율이 아닙니다. 실제 DB·플러그인 준비 비용은 별도로 남습니다.

## 수정

- 사용처가 없는 Tilt Prism·Yellowtail의 Google Fonts CSS 링크를 제거했습니다.
- KaTeX CSS는 설치된 패키지에서 앱 CSS에 포함하도록 변경했습니다. 수식 스타일과 폰트는 같은 서버에서 제공하며 수식 렌더러·출력 형식은 유지합니다.
- PC와 모바일의 캐릭터 편집기·개발 도구 진입점을 모두 동적 import로 전환했습니다. 초기 정적 소스 의존 경로는 326개에서 311개로 줄었으며 기존 소스 15개·372,799 B를 추가로 분리했습니다.
- 도구 코드를 기다리는 동안 닫을 수 있으며, 캐릭터 삭제·화면 이탈 뒤 늦게 끝난 import가 도구를 다시 표시하지 않도록 기존 경계를 사용합니다.

앱에서 명시적으로 선택한 사용자 폰트·커스텀 CSS는 변경하지 않습니다. 인증·가져오기 보호,
플러그인 초기화·V2 사전 로딩, 모델 등록·저장 감시·서버 저장 형식도 유지합니다.

## 검증

- 앱 회귀 테스트: **1,759개 통과**, 3개 건너뜀
- 타입 검사: 오류 0개, 기존 접근성 경고 4개
- 모바일 통합 테스트: 초기 채팅에서 편집기·개발 도구 import 없음, 명시적 진입에서만 import, 대기 중 닫기·캐릭터 삭제 후 안전한 복귀
- CSS 개발 변환 검증: 실제 `src/styles.css`에서 KaTeX 규칙을 확인하고 로컬 폰트 두 개의 HTTP 200과 본문 수신을 확인
- `git diff --check` 통과

## v8 프로덕션 빌드 확인

후속 요청으로 v8 프로덕션 빌드가 성공했습니다. 실제 Node 서버·임시 DB·Chromium에서
PC·모바일 부팅, 인증·재접속, 설정 열기·닫기의 런타임 예외는 0개였습니다.
빌드 HTML의 외부 초기 stylesheet는 0개이며, KaTeX 규칙이 포함된 CSS와 수식 폰트
두 개(28,076 B·6,912 B)의 서버 응답 HTTP 200을 확인했습니다.

HTML에 직접 연결된 JS 합계는 v7의 비압축 4,751,682 B·gzip 1,297,164 B에서
v8의 비압축 4,509,961 B·gzip 1,256,860 B로 줄었습니다. gzip 합계 감소는 약 3.1%이며
스타일 대기 제거·캐시 I/O 개선 효과와 다른 지표입니다. 공유 청크 분리로 파일 수는
53개에서 61개로 늘었으므로 요청 수가 감소했다고 해석하지 않습니다. 전송 헤더·동적 요청·
브라우저 캐시는 이 합계에 포함하지 않았으며, 사용자 실제 기기 시간은 아직 측정하지 않았습니다.
