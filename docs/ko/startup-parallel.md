# 초기 로딩의 독립 작업 동시 실행

`v1.17.0-datalite.9`에 포함하는 변경입니다. GitHub Release 워크플로는 검사·빌드·포터블 기동 확인 후 게시합니다.
이전 [DB 읽기 대기 단축](database-load-performance.md)에 이어 독립적인 읽기를 겹치고 중복 조회를 줄입니다.

## 변경한 실행 순서

| 작업 | 실행 방식 | 지켜야 하는 순서 |
| --- | --- | --- |
| 백업 알림 설정 | 가져오기 상태·인증 확인에 성공하면 DB 읽기와 함께 시작 | 실제 알림은 기존처럼 플러그인·DB 준비 후 첫 화면 진입 전에 표시. 상태 확인에 실패했다면 DB 읽기 이후 설정 조회로 복귀 |
| 플러그인 저장소 목록 | DB 읽기 또는 새 DB의 최초 저장 확인 후 선읽기 시작 | 서버의 구형 플러그인 데이터 이관 이후 시작. DB 디코딩·적용은 목록 완료를 기다리지 않으며, 플러그인 실행은 공유된 초기화 Promise를 기다림 |
| 플러그인 캐시의 etag·revision 목록 | 동일한 IndexedDB 메타데이터 스캔 한 번으로 함께 수집 | 본문 저장소를 읽지 않음. 목록별 최대 100,000개 한도·누락 시 서버 복구 유지. 구형 캐시 어댑터는 두 조회를 동시에 시작 |
| Google·Anthropic 모델 목록 | 동적 모델 등록이 켜져 있고 각 인증값이 있을 때 두 요청을 함께 시작 | 결과 등록은 Google → Anthropic 순서 유지. 중복 모델 우선순위와 개별 요청 실패 처리 유지 |

모델 목록 요청은 원래도 `loadedStore` 활성화 이후의 작업입니다. 이 변경은 백그라운드 목록 준비를 개선하며,
첫 화면을 가로막던 작업을 제거한 것으로 계산하지 않습니다.

DB 캐시 본문 읽기와 서버 revision 확인의 동시 실행, 첫 화면 이후 선택적 캐시 저장은 앞선 변경을 유지합니다.
새 UI·폴링·외부 목록 요청은 추가하지 않습니다.

## 병렬화하지 않은 작업

인증·가져오기 차단 확인 → DB 읽기/최초 저장 → DB 디코딩·적용 → 플러그인 준비·실행 →
형식 확인 → 활성화된 백업 알림 → 첫 화면 진입의 의존 관계는 유지합니다.
V2 플러그인은 동기 저장소 API를 사용하므로 전체 사전 준비가 끝나기 전에 실행하지 않습니다.
선읽기에 실패하면 기존 플러그인 초기화 경로에서 재시도합니다.

동시 실행은 I/O 대기를 겹치는 방식입니다. JavaScript의 DB 디코딩·정규화 CPU 작업을
여러 코어로 나누는 변경은 아니며, CPU 작업 중에는 네트워크 응답 처리가 늦어질 수 있습니다.

## 측정과 검증

기존 Performance 항목에 `plugins-index-prefetch`를 추가했습니다. `plugins`와 겹칠 수 있으므로
두 시간을 더해 전체 시간으로 해석하지 않습니다. 전체 항목 조회 방법은
[초기 로딩 구조와 최적화](startup-performance.md#기기에서-느린-구간-확인)에 있습니다.

자동 테스트는 DB/최초 저장 완료 전 선읽기 금지, 선읽기 실패, 초기화 Promise 공유,
모델 목록의 동시 요청·등록 순서·중복·개별 실패, 단일 메타데이터 스캔과 구형 어댑터의 동시 조회를 확인합니다.
가상 시계에서는 300ms DB 읽기와 500ms 백업 설정 조회가 500ms에 함께 준비되는 것을 검증했습니다.
이는 제어된 지연 시험이며 사용자 서버·Android의 실제 로딩 시간은 아닙니다.

실제 Chromium에서도 8 MiB 캐시의 서버 확인 선시작, 메타데이터 단일 스캔·본문 읽기 0회,
DB 완료 이후의 비차단 목록 선읽기 순서를 확인했습니다. 이 브라우저 검사는 실제 소스 모듈을 사용하는
분리된 하네스이며 전체 앱·사용자 DB·실제 Android의 통합 성능 측정은 아닙니다.

검증 결과: 앱 전체 **1,796개 통과**, 3개 건너뜀. Svelte/TypeScript 오류 0개,
기존 `DefaultChatScreen.svelte` 접근성 경고 4개이며 `git diff --check`도 통과했습니다.

v9 배포 준비 시 프로덕션 빌드와 실제 Node 서버·Chromium의 PC/모바일 부팅·인증·재접속·
설정 열기/닫기도 확인했습니다. 페이지당 목록 조회 1회, 재접속 DB `304`,
첫 화면 준비 이후의 선택적 캐시 쓰기를 확인했고 런타임 예외는 없었습니다.
빈 테스트 DB를 사용하고 외부 인터넷 요청을 차단한 검사이므로 실제 기기 속도 수치는 제공하지 않습니다.
