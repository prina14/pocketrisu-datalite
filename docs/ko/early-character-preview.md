# 캐릭터 이름을 먼저 표시하는 부팅 화면

v1.17.0-datalite.12에 포함된 변경입니다. 저장 기준 초기화·서버 복사 감소 최적화와 함께 적용합니다.

## 표시 순서

인증·가져오기 차단 여부 확인과 최신 DB 읽기·적용이 끝나면, 플러그인과 저장 초기화를
기다리는 동안 실제 캐릭터 이름을 먼저 표시합니다. 이름은 최대 40개로 제한하고 휴지통 항목을
제외합니다. 새 DB나 복구된 DB도 기존 기본값 적용 후 표시합니다.

이것은 기존 편집 화면을 미리 활성화하는 방식이 아닙니다. 미리보기에는 버튼·입력·링크·
이미지·iframe이 없어 선택·전송·편집을 수행하지 않으며, 서버 쓰기와 추가 미디어 다운로드도
발생시키지 않습니다. 캐릭터가 많은 경우에도 목록 전체 UI나 대화 본문을 조기에 만들지 않습니다.
이름은 Svelte 텍스트로 이스케이프해 표시합니다. 목록은 DB 배열 순서이며 최종 화면의 폴더별
배치와 다를 수 있습니다. 기존 그림을 흉내 내기 위해 이미지를 추가로 요청하지 않습니다.

최종 준비가 끝나면 기존 화면으로 전환합니다. 백업 알림 확인·플러그인 준비·형식 이관·
저장 기준과 감시 설치 순서는 유지합니다. 계정 가져오기 중이면 가져오기 화면이 우선하고,
차단 여부를 확인하지 못한 부팅에서는 미리보기를 생략합니다. 초기화 실패 시 미리보기를
지우고 기존 오류 표시를 사용합니다.

## 렌더링 기회

이름을 실제로 표시할 기회를 주기 위해 다음 작업 전에 두 번의 animation frame을 기다립니다.
일반적으로 한두 프레임의 시간이 추가될 수 있어 전체 초기화 완료가 무조건 빨라지는 변경은
아닙니다. 숨겨진 탭은 기다리지 않고, throttling 시에는 100ms 타이머로 복귀합니다.
이는 명목상 타이머이며 브라우저가 정지하면 실행 자체도 늦어질 수 있습니다.

`navigation-to-preview-frame`은 navigation 이후 미리보기 렌더링 기회까지,
`navigation-to-ui-frame`은 최종 UI 준비 후 렌더링 기회까지입니다. `preview-frame`은
미리보기 공개 뒤의 프레임 대기입니다. 실제 디스플레이 페인트·모든 이미지 수신 완료를
보장하는 이벤트는 아니며 각 항목을 합산하지 않습니다.

## 검증 범위

- 이름 수 제한·휴지통 제외·원본 불변, 프레임 대기·throttling 복귀·숨김 탭 처리 시험.
- 실제 Svelte 컴포넌트에서 텍스트 이스케이프·읽기 전용·미디어 요소 없음 확인.
- App에서 준비 전 표시·가져오기 화면 우선·준비 완료 후 제거 확인.
- Chromium에서 실제 미리보기 컴포넌트와 프레임 함수를 실행해 준비 완료 전 표시·제거 확인.
  이는 분리된 하네스이며 전체 프로덕션 App이나 실제 Oracle·Android의 시간 측정은 아닙니다.
- 앱 전체 **1,827개 통과**, 3개 건너뜀. 타입 오류 0개, 기존 접근성 경고 4개.
- 함께 유지한 저장·서버 수정의 서버 검사 252개, 호환성 검사 154개 통과(호환성 6개 건너뜀).
- `git diff --check` 통과.

프로덕션 빌드 이후 실제 Node 서버·Chromium에서도 PC 첫 로그인과 모바일 재접속을 확인했습니다.
두 경우 모두 캐릭터 이름이 최종 UI보다 먼저 표시되고 완료 후 제거됐습니다. 미리보기의 제어·
미디어 요소는 0개였으며 DB delta 복원과 설정 열기·닫기에서 런타임 예외가 없었습니다.
합성 데이터와 외부 요청을 차단한 로컬 환경의 검사로, 실제 Oracle·Android 측정은 아닙니다.
