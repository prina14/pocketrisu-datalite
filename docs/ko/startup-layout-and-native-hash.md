# 로딩 화면의 레이아웃 연속성과 브라우저 해시 계산 개선

v1.17.0-datalite.18에 포함된 변경입니다.

## 화면

첫 HTML과 앱의 빈 로딩 화면·인증된 이름 미리보기가 동일한 `src/etc/startup-layout.html` 틀과
`src/styles/startup-shell.css`를 사용합니다. Vite의 HTML 변환에서 틀과 CSS를 인라인하므로
첫 화면을 위해 별도 CSS·폰트·이미지·외부 캐릭터 목록을 요청하지 않습니다.

PC는 80px 메뉴 레일·넓은 화면의 384px 최근 대화 패널·홈 제목과 접힌 Realm 영역을,
모바일은 64px 검색 헤더·캐릭터 관리 탭/목록·80px 하단 메뉴 공간을 유지합니다.
캐릭터 사진·채팅 개수 대신 자리 표시자를 쓰며, 작은 인증 응답의 이름만 textContent로 삽입합니다.
로딩 중의 메뉴·검색·링크는 입력/작업을 실행하지 않는 표시용 요소입니다.
DBState·저장 기준·플러그인 초기화 전의 편집 및 채팅 동작은 추가하지 않습니다.
사용자 설정에 따른 최종 화면의 모든 변형을 사전에 복원하는 기능은 아닙니다.

## 변경분 처리

HTTPS/localhost의 `crypto.subtle.digest`로 SHA-256을 계산합니다. manifest의 해시 작업은
한 번에 최대 64개로 제한합니다. HTTP 또는 WebCrypto 실패 시 기존 JavaScript SHA-256으로 복구합니다.
변경분 적용은 요청에 사용한 manifest의 조각 길이를 재사용해 같은 원본을 다시 스캔하지 않습니다.
최종 전체 SHA-256·패킷 길이·범위 검증을 유지하고, 실패 시 기존 전체 읽기 복구 경로를 사용합니다.
기존 동기 API와 패킷 형식은 유지합니다.

Chromium 개발 서버의 약 12MiB 합성 데이터 두 차례 시험에서 manifest 약 136–151 → 29–32ms,
변경분 적용 약 128–129 → 17–19ms로 측정됐습니다. 두 경로의 manifest와 복원 결과가 일치했습니다.
로컬 합성 시험이며 실제 Android의 개선율을 보장하지 않습니다.

## 초기 대기 관찰

인증·이름 목록·읽기 응답의 Server-Timing에 `event-loop-recent-max`를 추가했습니다.
최근 약 5초의 이벤트 루프 지연과 늦어진 샘플 타이머를 관찰하는 진단값입니다.
`request-to-handler` 이전에 발생한 서버 정체를 살펴보는 참고값이며,
해당 요청의 처리 단계가 아니므로 다른 단계 시간과 더하지 않습니다.
네트워크 지연을 직접 측정하거나 간헐적인 초기 대기가 해결됐음을 보장하지 않습니다.


## 검증

앱 1,845개·서버 282개·호환성 154개 통과(앱 3개·호환성 6개 건너뜀),
타입 오류 0개·기존 접근성 경고 4개입니다. 개발 서버·Chromium에서 PC/모바일의 첫 HTML과
마운트 후 미리보기의 주요 좌표가 일치하고, 외부 스타일시트·미디어·편집 제어가 추가되지 않음을 확인했습니다.
프로덕션 빌드·실제 Node 서버·Chromium에서도 PC/모바일·첫 로그인·늦은 목록 인계를 확인했습니다.
실제 NodeStorage에서 약 11.44MB DB 변경분의 네이티브 digest 호출을 확인했으며,
manifest 30ms·변경분 적용 18ms로 측정됐습니다. 원격 Oracle에서의 개선율을 뜻하지 않습니다.
릴리스 검증은 해당 버전의 릴리스 노트도 참조하세요.
