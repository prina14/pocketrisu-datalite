# PocketRisu DataLite 17 — 작은 변경분 응답과 초기 목록 인계 개선

작은 DB 변경분을 받으려고 전체 DB의 압축 완료를 기다리던 경로를 줄이고,
앱 시작 후 늦게 도착한 캐릭터 목록도 먼저 표시합니다.

## 변경

- `/api/` 요청의 정적 파일 검사를 제거했습니다. 압축과 같은 libuv 작업 풀에 불필요한 파일 검사를 보내지 않습니다.
- 최신 DB의 조각 경계·SHA-256 준비를 단일 워커로 옮겼습니다. 진행 중인 결과를 공유하고 구버전 결과를 최신 DB에 적용하지 않습니다.
- 해당 압축 완성본이 없고 delta 원본이 전체의 1% 이하·압축 본문이 16 KiB 이하이면 전체 압축 비교 없이 delta를 바로 보냅니다.
  전체 값이 극히 잘 압축되는 경우에는 전체 응답보다 최대 16 KiB 더 보낼 수 있는 제한된 절충입니다.
- 준비된 압축 결과가 있거나 변경분이 큰 경우에는 기존 크기 비교를 유지합니다. 캐시가 없는 gzip·Brotli 비교는 가능한 경우 조기 종료합니다.
- 앱 마운트 후 인증 대기 중 도착한 작은 캐릭터 목록을 화면에 인계하고 목록 표시 시점을 기록합니다.
- 인증·목록·읽기에 `request-to-handler` 측정을 추가했습니다. 기존 통합 콘솔 코드를 그대로 사용할 수 있습니다.

저장·백업·delta 패킷 형식과 전체 SHA-256 검증, 인증·세션 권한·가져오기 차단은 유지합니다.
캐시 기본 상한은 64 MiB입니다. 별도로 단일 워커 런타임과 최대 32 MiB 입력 사본이 필요하며,
더 큰 입력이나 워커 실패 시 기존 계산으로 복구합니다. HTTPS 도구와 설치 경로는 바꾸지 않습니다.

## 검증

- 앱 1,843개·서버 280개·호환성 154개 통과. 앱 3개·호환성 6개 건너뜀.
- 타입 오류 0개, 기존 접근성 경고 4개. 프로덕션 빌드 완료.
- 실제 Node 서버·Chromium: PC·모바일·첫 로그인·마운트 후 늦은 목록 응답·인증 대기 중 목록 표시·설정 열기/닫기 확인, 런타임 예외 없음.
- 약 12.65MB 합성 DB의 캐시 없는 Brotli 변경분 요청 5회 중앙값: v16 104.53ms → v17 71.12ms.
  해당 시험의 전송 바이트와 패킷·복원 SHA-256은 일치했습니다. 실제 서버의 전체 로딩 개선율은 별도 확인이 필요합니다.

## 업데이트 후 확인

Linux x64 포터블을 제공합니다. 기존 앱의 커스텀 업데이트 기능으로 적용하면 되며 서버에서 빌드할 필요는 없습니다.

같은 일반 브라우저에서 서버 재시작 후 첫 접속, 바로 새로고침, 채팅 저장 후 새로고침을 비교해 주세요.
기존 통합 콘솔 코드의 `navigation-to-list-frame`, `navigation-to-ui-frame`,
`read-compress-compare`, `request-to-handler`를 확인하면 됩니다. 캐시를 지울 필요는 없습니다.
