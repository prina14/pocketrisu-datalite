# PocketRisu DataLite 25 — 캐릭터 열람 활동의 중복 목록 요청 줄이기

캐릭터 열람 활동을 기록한 직후 목록을 다시 받던 POST → GET을 새 클라이언트·서버 조합에서 POST 한 번으로 처리합니다. 서버가 명시적인 요청 헤더를 받았을 때만 최신 목록과 ETag를 함께 반환합니다. 구형 서버에서는 기존 GET으로 돌아가며, 구형 클라이언트 응답은 바꾸지 않습니다.

다른 기기의 활동과 요청 도중 발생한 새 열람 기록을 보존합니다. 실제 채팅 전송이나 사용자 설정을 변경하는 기능은 추가하지 않았습니다. 인증, DB revision 재검증, 해시·저장 프로토콜은 유지합니다.

## 검증과 한계

- 관련 클라이언트·채팅·저장 해시 회귀 테스트 137개, 서버 응답 협상 테스트 2개 통과.
- 타입 오류 0개, 변경하지 않은 파일의 기존 접근성 경고 4개.
- 실제 소스의 Chrome 하네스에서 요청당 150ms 지연을 적용하고 7회씩 교차 비교: 활동 동기화 평균 약 582ms → 415ms, 요청 2회 → 1회. 최초 250ms debounce 포함. 전체 앱·Oracle 서버 속도 개선율을 뜻하지 않습니다.
- DataLite 24 실서버의 새로고침 7회는 UI 프레임 평균 1.226초였습니다. 캐릭터 진입→홈→새로고침과 캐릭터 화면에서 새로고침도 별도 측정했습니다. 채팅은 전송하지 않았습니다.

전체 초기 화면 속도를 크게 줄였다고 주장하지 않습니다. 네트워크 대기 편차와 저장 기준 해시 CPU 비용은 별도 과제입니다. 효과가 없거나 더 느렸던 문자열 해시 루프 수정은 포함하지 않았습니다. 릴리스 Actions에서 전체 검사·빌드·포터블 기동을 추가 검증합니다.
