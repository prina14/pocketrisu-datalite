# PocketRisu DataLite 14 — 공인 IP HTTPS 자동 설정·복구 명령

기존 `https://공인IP:6001` 접속을 위해 포터블 루트에 `https.sh`를 추가했습니다.
웹 설정 버튼이 아니라 Ubuntu 서버에서 관리자 권한으로 한 번 실행하는 도구입니다.
기존 설치 경로·리수 실행 포트·서비스의 ExecStart를 유지합니다.

## 사용

업데이트 후 기존 설치 폴더에서 실행합니다.

```bash
sudo bash ./https.sh
```

최초에는 Oracle 공인 IPv4를 입력합니다. 인증서 도구·자동 확인 타이머·서비스 시작 전 복원을 설정하고,
공인 IP용 인증서를 발급해 리수에 적용합니다. 서비스명은 기본 `risu.service`, 접속 포트는 6001입니다.
이후에는 다음 명령 하나로 저장된 설정을 사용해 갱신·복구할 수 있습니다.

```bash
sudo pocketrisu-https
```

## 동작과 조건

- Certbot 5.3+의 IP 인증서·shortlived 프로필을 사용합니다. 필요하면 공식 certbot snap을 설치합니다.
- **Oracle 보안 규칙과 서버 방화벽에서 TCP 80·6001 접근이 가능해야 합니다.** 방화벽이나 Tailscale 설정을 자동 변경하지 않습니다.
- 인증서 원본·복원용 사본·도구와 설정을 리수 설치 폴더 밖에 보관합니다. 서비스 시작 전에 유실된 인증서 파일을 복원합니다.
- 약 6시간 간격으로 갱신 여부를 확인합니다. 강제 재발급하지 않으며 인증서와 HTTPS가 정상이라면 재시작하지 않습니다.
- IP·만료·개인 키 일치를 검증하고, 적용 파일은 서비스 사용자 권한으로 생성합니다. 개인 키 권한은 0600으로 제한합니다.
- 발급 실패 시 기존 리수 프로세스를 중지하거나 인증서 파일을 교체하지 않습니다. 다른 프로그램이 80 포트를 사용하면 중지하지 않고 안내합니다.
- 인증서 적용이 필요하면 서비스가 재시작되므로 진행 중인 채팅을 마친 뒤 실행하세요.
- HTTP에서 HTTPS로 바뀌면 기존 HTTP 대상으로 설정한 Tailscale Serve 접속은 영향을 받을 수 있습니다. 성공 후 공인 IP의 HTTPS 주소로 접속합니다.

## 검증

HTTPS 도구의 공인 IP 판정, 인증서·키 검증, 유실 파일 복원과 권한, 심볼릭 링크 처리,
발급 실패 시 미적용, 서비스 시작 전 복원·타이머 구성 등을 검사했습니다.
모의 인증서로 실제 리수 서버를 실행하고 인증서 검증을 유지한 HTTPS 연결도 확인했습니다.
실제 Oracle에서의 공인 인증서 발급·방화벽·systemd 설정 적용은 개발 환경에서 수행하지 않았습니다.
프로덕션 앱 빌드와 Linux x64 포터블 생성·실행 검증을 거쳐 배포합니다.
