# PocketRisu DataLite 16 — 로딩 응답 재사용·Brotli 압축 선택 유지

최신 DB의 전송 완성본과 조각 해시를 재사용하고, 작은 캐릭터 목록을 먼저 표시합니다.
v15에서 추가한 재사용 경로가 gzip을 우선하던 부분을 보완해, 기존 HTTPS 브라우저의 Brotli 선택과
압축 품질을 유지하면서 완성본을 재사용합니다.

## 변경

- 캐릭터 이름 최대 40개를 작은 인증된 API로 먼저 표시합니다. 앱 본체 로딩과 병렬이며 첫 로그인은 인증 후 요청합니다.
- 서버가 최신 한 버전의 바이너리·ETag·gzip·Brotli·조각별 해시를 준비해 재사용합니다. 기본 보관 상한은 64 MiB입니다.
- 기존 압축 미들웨어와 같은 협상 방식으로 Brotli·gzip의 우선순위와 품질값을 존중합니다. Brotli 품질 4를 유지하고 중복 압축을 피합니다.
- delta와 전체 응답은 선택한 압축 방식의 크기로 비교합니다. 패킷·조각 경계·전체 SHA-256 검증은 유지합니다.
- 작은 목록은 읽기 전용이며 채팅·편집은 기존 플러그인·저장 준비 이후 활성화합니다. 전체 DB 다운로드는 계속 진행합니다.

## 검증

같은 약 12.65MB 합성 DB를 사용하는 v14 대비 로컬 HTTP 5회 중앙값:

| 압축·요청 | v14 | 수정 후 |
| --- | ---: | ---: |
| gzip 전체 | 197.54ms | 9.37ms |
| gzip delta | 81.96ms | 5.71ms |
| Brotli 전체 | 88.42ms | 8.09ms |
| Brotli delta | 89.77ms | 8.81ms |

각 방식에서 두 서버의 전송 바이트·패킷·복원 내용이 일치했습니다. 로컬 합성 시험이며
실제 Oracle·Android의 전체 로딩 개선율을 보장하지 않습니다.

프로덕션 빌드·Node 서버·Chromium에서 DB 응답을 5초 지연해도 실제 이름은 먼저 표시됐습니다.
PC 시험의 목록 렌더링 기회는 117ms, 전체 DB 적용 후 미리보기는 5,641ms였습니다.
모바일과 첫 로그인, 로그인 전 이름 미노출, 설정 열기·닫기에서 런타임 예외는 없었습니다.

앱 1,840개·서버 275개·호환성 154개 검사 통과(앱 3개·호환성 6개 건너뜀).
타입 오류 0개, 기존 접근성 경고 4개입니다. 저장·백업 형식, 플러그인 API, 세션 권한,
HTTPS 설정·복구 도구와 기존 업데이트 경로는 유지합니다.

## 업데이트·측정

Linux x64 포터블을 제공합니다. 기존 업데이트 기능으로 적용하며 설치 서버에서 빌드할 필요가 없습니다.
기존 측정 코드에서 `navigation-to-list-frame`으로 실제 이름의 첫 표시 기회,
`navigation-to-ui-frame`으로 최종 화면의 렌더링 기회를 구분할 수 있습니다.
