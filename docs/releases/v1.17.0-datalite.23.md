# PocketRisu DataLite 23 — 앱 코드와 DB 읽기를 병렬로 준비

기존에는 큰 앱 코드의 다운로드·실행이 끝나야 인증과 DB 읽기가 시작됐습니다.
유효한 로그인 쿠키가 있는 접속에서는 작은 전송 모듈이 먼저 인증하고,
앱 코드를 받는 동안 기존 캐시/변경분/전체 DB 읽기를 병렬로 수행하도록 바꿨습니다.

## 변경 사항

- 초기 전송 모듈의 정적 의존성은 약 106 kB입니다. 화면·DB 디코더·플러그인 실행·로그인 UI를 이 모듈에서 분리했습니다.
- 같은 NodeStorage 인스턴스를 앱에 인계해 인증과 세션을 중복 생성하지 않습니다.
- 미리 받은 사본은 메모리에서 재사용합니다. 앱이 실제 적용할 때 revision/ETag를 다시 확인하며, 다른 기기에서 변경됐다면 기존 delta 또는 전체 읽기로 갱신합니다.
- DBState 적용·플러그인·형식 변환·저장 기준 초기화는 기존 순서를 유지합니다. 사전 읽기는 DB를 저장하거나 편집 화면을 활성화하지 않습니다.
- 첫 로그인·만료된 쿠키·새 서버의 비밀번호 설정은 기존 로그인 UI가 처리합니다. 사전 읽기에서 비밀번호 창을 띄우지 않습니다. 알려진 import 차단 상태가 없으면 사전 DB 읽기를 시작하지 않습니다.
- 앱 다운로드가 길어져 인증 시점의 import 상태가 1초 이상 지났다면 현재 상태를 다시 확인합니다.
- 초기 로딩 화면의 터치를 이후 자동 저장의 writer 전환 근거로 삼지 않습니다.
- 업데이트·후원·Proton 가져오기·폴더 설정·플러그인 오류 창은 실제 열 때 불러오고, 한번 로드한 인스턴스는 유지해 닫았다 열 때 상태가 사라지지 않게 했습니다. 메모리 진행 창과 계정 가져오기 화면도 필요할 때 불러옵니다.
- 빌드 검사에서 초기 전송 모듈에 앱 본체가 섞이거나 정적 의존성이 256 KiB를 넘으면 배포를 중단합니다. v22의 압축 파일 원본 일치 검사도 유지합니다.

## 검증과 효과

같은 로컬 Node 서버·합성 DB·Chromium에서 공개 v22 포터블의 프런트엔드와 수정 버전을 비교했습니다.
앱 진입 파일을 약 3초 동안 대기시키고 DB 응답에 5초 대기를 추가한 통제된 조건입니다.

| 측정 | v22 | v23 |
| --- | ---: | ---: |
| 앱 진입 파일을 기다리는 동안 DB 요청 시작 | 아니요 | 예 |
| `navigation-to-preview-frame` | 8.611초 | 5.631초 |
| `navigation-to-ui-frame` | 8.678초 | 5.751초 |

인위적인 대기로 순차/병렬 처리를 검증한 결과이며 실제 회선에서 2.9초가 항상 줄거나
모든 접속이 1초 안에 끝난다는 뜻은 아닙니다. 처음 로그인하는 브라우저는 로그인 후 DB를
받는 기존 절차를 사용합니다. 닫힌 부가 창의 지연 로딩은 이 경우에도 적용됩니다.

PC·모바일·최초 로그인 전 이름 미노출·설정 열기/닫기·실제 채팅 열기·입력 보호·단순 열람 후
DB 불변·v22의 준비된 delta·저장 통신 4회 실패 후 복구를 확인했습니다. 닫힌 부가 창을
부팅 때 다운로드하지 않으며, 모의 업데이트 알림을 보내면 실제 업데이트 창이 로드되고
정상적으로 열리고 닫히는 것도 확인했습니다.

## 적용과 테스트

기존 커스텀 자동 업데이트로 v23을 적용할 수 있습니다. Linux x64 포터블은
`PocketRisu-v1.17.0-datalite.23-linux-x64.tar.gz`입니다. 서버에서 다시 빌드할 필요가 없습니다.

기존 [통합 진단 v3](../ko/diagnostics/check-db-sync.browser.js)를 그대로 사용합니다.
화면이 나온 뒤 약 10초 후 실행하세요. 캐시를 지우지 않은 일반 접속과 새 브라우저 첫 로그인을
구분해서 비교하면 됩니다.

- `early-storage-prefetch`: 앱 코드와 병렬로 시작한 인증·DB 읽기 전체.
- `early-database-*`: 사전 읽기의 세부 단계.
- `early-storage-wait`: 앱이 사전 읽기의 남은 부분을 기다린 시간.
- `startup-copy-reused`: 인계된 메모리 사본을 재사용한 진단 이벤트.

시간은 서로 겹치므로 합산하지 않습니다. 전체 화면 준비는 기존 `navigation-to-ui-frame`으로
비교하세요. [기술 설명](../ko/early-storage-pipeline.md).
