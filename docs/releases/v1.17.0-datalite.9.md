# PocketRisu DataLite 9 — 로컬 저장 파일 읽기·동시 로딩 개선

`v1.17.0-datalite.8`에 이어 `Loading Local Save File...` 구간의 직렬 대기와 초기 준비의 중복 작업을 줄였습니다.
서버 저장·백업 형식, 인증, 플러그인 API와 single-writer 정책은 유지합니다.

## DB 읽기

- IndexedDB의 작은 버전 메타데이터가 먼저 도착하면 서버 revision 확인을 시작하고, 큰 캐시 본문 읽기와 겹칩니다.
- 실제 캐시 본문의 etag·revision이 확인 요청의 정보와 같을 때만 `304` 응답으로 재사용합니다. 사본 누락·불일치는 다시 읽고, 인증 실패를 캐시로 가리지 않습니다.
- 초기 DB의 선택적 캐시 재저장은 첫 화면의 렌더링 기회 이후로 미룹니다. 서버의 실제 저장을 미루는 변경은 아닙니다.
- 지연 저장과 후속 캐시 쓰기는 순서를 보장하고, 오래된 대기 사본은 새 사본으로 대체합니다. 선택적 캐시 실패가 유효한 서버 읽기를 실패시키지 않습니다.
- 구형 서버가 버전 확인 대신 정상 본문을 반환하면 같은 응답을 재사용합니다.

## 독립 작업의 동시 실행

- 인증·가져오기 상태 확인 후 백업 알림 설정을 DB 읽기와 함께 조회합니다. 기존 백업 알림 표시 시점은 유지하며, 인증 확인에 실패했다면 기존 조회 순서로 복귀합니다.
- DB 읽기 또는 새 DB의 최초 저장이 끝나면 플러그인 저장소 목록을 선읽기합니다. 서버의 구형 저장소 이관 이전에는 시작하지 않고, 실제 플러그인 실행은 준비 완료를 기다립니다.
- 플러그인 캐시의 etag·revision을 메타데이터 스캔 한 번으로 수집합니다. 본문은 읽지 않으며 구형 어댑터는 두 조회를 함께 시작합니다.
- 동적 Google·Anthropic 모델 목록 요청을 함께 시작합니다. 등록은 기존 Google → Anthropic 순서를 유지하고 한쪽 요청이 실패해도 다른 결과를 처리합니다. 이 요청들은 원래도 첫 화면 진입 이후의 작업입니다.
- 구간별 Performance 측정으로 캐시 읽기·서버 확인·본문 수신·delta 복원·캐시 쓰기와 목록 선읽기를 구분할 수 있습니다.

## 검증과 한계

- 앱 테스트 **1,796개 통과**, 3개 건너뜀. 타입 오류 0개, 기존 접근성 경고 4개.
- 서버 테스트 **241개 통과**, 저장소·백업·업데이트 호환성 **153개 통과**, 6개 건너뜀.
- v9 프로덕션 빌드 성공. 실제 Node 서버·Chromium의 PC/모바일 부팅·인증·재접속·설정 열기/닫기에서 런타임 예외 0개. 재접속은 DB `304` 재사용, 페이지당 플러그인 목록 조회 1회이며, 선택적 캐시 쓰기는 첫 화면 준비 이후 실행되는 것을 확인했습니다. 빈 테스트 DB와 외부 인터넷 요청을 차단한 환경의 검사입니다.
- 캐시 누락·불일치·인증 실패·구형 서버·쓰기 순서·저장 실패 복구, 선읽기 의존 관계·초기화 공유, 모델 등록 순서·중복·개별 실패를 검증했습니다.
- 실제 Chromium에서 8 MiB IndexedDB 사본의 메타데이터 → 서버 확인 시작 → 본문 완료 순서, 단일 메타데이터 스캔과 본문 조회 0회, DB 준비 이후의 비차단 선읽기를 확인했습니다.
- 위 브라우저 모듈 시험과 제어된 지연 시험은 실제 Android·사용자 DB의 속도 측정이 아닙니다. DB 디코딩·정규화의 CPU 작업을 여러 코어로 나누는 변경은 아니며, 최초 다운로드와 V2 플러그인 전체 준비 비용은 남습니다.
- GitHub Release는 앱·서버 검사와 빌드, Linux x64 포터블 조립·서버 기동 확인 후 공개합니다.

## 업데이트

Oracle Ubuntu x86_64용 포터블을 제공합니다. 설치 서버에서 프런트엔드를 빌드할 필요가 없으며,
기존 설치 경로·자동실행 설정과 `save/`·`backups/`를 유지할 수 있습니다.
`RisuAI-NodeOnly-` 파일은 구형 자동 업데이트와 호환하기 위한 동일 패키지입니다.
