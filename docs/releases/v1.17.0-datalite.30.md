# DataLite 30 — 플러그인의 중복 전체 대화 다운로드 제거

캐릭터를 열 때 화면의 변경분 조회와 별도로 플러그인 `getChatFromIndex`가 같은 대화 전체를 내려받는 문제가 있었습니다. 사용자 HAR에서 화면 요청은 캐시 검증 309바이트였지만 플러그인 요청은 507,464바이트였습니다. 메시지를 입력하지 않아도 플러그인의 읽기 호출만으로 발생했습니다.

- UI와 플러그인의 동시 읽기는 같은 캐시 검증 요청을 공유합니다. 여러 플러그인의 동시 읽기도 합칩니다.
- 열지 않은 대화를 플러그인이 조회할 때도 메시지·로어북 사본을 검증해 재사용합니다. 읽기만으로 앱의 대화 상태를 불러오거나 저장하지 않습니다.
- 플러그인에는 별도 복사본을 반환합니다. 플러그인이 복사본을 수정해도 화면이나 캐시에 직접 반영되지 않습니다. 내보내기·백업의 전체 읽기는 유지합니다.

관련 검사 97개, 타입 검사 오류 0개. 실제 V3 메서드와 캐릭터 4개·새로고침 4회 모의 회귀검사도 포함합니다. 실제 서버에는 활성 캐릭터가 3개여서 활성 상태를 바꾸지 않고 3개를 각각 4회 검증했습니다. 12회 모두 UI와 플러그인 동시 읽기가 요청 1회였고, 재진입의 대화 요청 실제 전송량은 307–309바이트였습니다. 내용 일치와 복사본 격리를 확인했고 실행 오류는 없었습니다.

프런트엔드 변경만 있어 PC 빌드 후 기존 Linux 실행환경을 유지하며 서비스 중지 없이 적용했습니다. DB·대화 본문·플러그인 설정의 마이그레이션은 없습니다. 수치는 대화 읽기 구간에 한하며 모든 페이지 요청의 합계나 첫 다운로드가 아닙니다. 첫 화면·플러그인 읽기 지연의 추가 개선은 별도 계측이 필요합니다.
