# PocketRisu DataLite 8 — 첫 화면 대기·대량 대화 최적화

`v1.17.0-datalite.7`에 이어 초기 로딩과 대화·캐릭터가 많은 환경의 반복 작업을 줄였습니다.
서버 저장·백업 형식과 인증·플러그인·single-writer 정책은 유지합니다.

## 초기 로딩

- 첫 화면을 막던 jsDelivr의 KaTeX CSS 의존을 제거했습니다. 수식 CSS·폰트는 설치된 패키지에서 빌드해 같은 서버에서 제공합니다.
- 사용처가 없는 Tilt Prism·Yellowtail의 Google Fonts CSS 요청을 제거했습니다. 사용자가 선택한 폰트·커스텀 CSS는 유지합니다.
- PC·모바일의 캐릭터 편집기와 개발 도구는 명시적으로 열 때 import합니다. 초기 정적 경로에서 기존 소스 15개·372,799 B를 추가 분리했습니다. 이는 실제 전송량 감소 수치가 아닙니다.
- 외부 CSS 3초 지연 제어 실험에서 대기를 제거하면 첫 콘텐츠 표시가 3,144ms에서 156ms로 줄었습니다. 동일 v7 JavaScript와 임시 HTML을 비교한 원인 재현이며, 실제 Android 개선율이나 v8 실사용 측정은 아닙니다.

## 많은 캐릭터·대화

- 대화 폴더 목록을 한 번 인덱싱합니다. 폴더마다 전체 대화를 두 번 필터링하고 각 행의 위치를 다시 찾던 작업을 줄였습니다. 복사·삭제 확인 후에는 기존처럼 최신 위치를 조회합니다.
- 접힌 캐릭터 폴더의 내부 행을 열 때만 만듭니다. 재정렬할 때는 저장된 소속을 복원해 DOM에 없는 캐릭터가 폴더 밖으로 빠지지 않도록 했습니다.
- 로컬 채팅 캐시를 IndexedDB version 2로 이관합니다. 대화 본문은 유지하고 별도 `recency` 저장소에서 최근 사용 시각만 갱신합니다. 이관은 기존 키·시각 인덱스를 사용해 모든 대화 본문을 읽지 않습니다.
- 사용 시각 갱신의 quota 실패가 유효한 캐시 읽기까지 실패시키지 않도록 했습니다. 본문·메타데이터 저장은 원자적이며 기존 LRU·quota 회수 정책은 유지합니다.
- 서버가 메시지 접두부를 검증하고 새 메시지·메타데이터가 모두 같으면 추가 전체 snapshot과 캐시 본문 재저장을 생략합니다. 메모·로어북·null·필드 삭제 등이 바뀌면 계속 최신 사본을 저장합니다.

저장된 메시지·캐릭터를 삭제하거나 축약하지 않습니다. 최초 긴 대화 읽기·접두부 fingerprint 계산,
펼친 대규모 목록의 렌더링, V2 플러그인 preload 비용은 남습니다. 이관된 브라우저 캐시를
이해하지 못하는 구버전 탭은 기존 오류 처리에 따라 네트워크로 읽을 수 있습니다.

## 검증

- 로컬 앱 테스트 **1,772개 통과**, 3개 건너뜀. 타입 오류 0개, 기존 접근성 경고 4개.
- v8 프로덕션 빌드 성공. 실제 Node 서버·Chromium에서 PC/모바일 부팅·인증·재접속·설정 열기/닫기, 로컬 수식 CSS·폰트 응답 확인. 확인 경로의 런타임 예외 0개.
- 100,000개 대화·1,000개 폴더에서 본문을 읽지 않는 목록 인덱싱 검증.
- 10,000개 대화·200개 폴더 합성 계산에서 폴더 정보 조회 4,000,000회 → 10,000회, 원본 슬롯 합계·순서 유지.
- 실제 Chromium IndexedDB에서 version 1의 20,000개 메시지 이관·재읽기·metadata quota 실패 시 내용 보존 검증. 재읽기는 본문 쓰기 0회, 작은 metadata 쓰기 1회.
- 캐릭터 1,000개가 든 접힌 폴더의 행 생성·열기·닫기, 10,000개 소속 캐릭터의 폴더 재정렬 보존 검증.
- GitHub Release는 앱·서버 검사, Linux x64 포터블 조립과 서버 실행 검사를 통과한 뒤 공개합니다.

## 업데이트

Oracle Ubuntu x86_64용 Linux x64 포터블과 SHA-256 파일을 제공합니다. 서버에서 프런트엔드를 빌드할 필요가 없습니다.
기존 설치 경로와 `save/`·`backups/`를 유지합니다. `RisuAI-NodeOnly-` 파일은 구형 자동 업데이트 호환용 동일 패키지입니다.
