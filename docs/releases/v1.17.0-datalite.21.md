# PocketRisu DataLite 21 — 저장 후 캐시 갱신과 로딩 화면 일치

접속 직후 자동 저장이 발생하면 첫 읽기의 브라우저 사본이 뒤처진 채 남아 다음 새로고침에서
변경분을 다시 받던 경로를 개선했습니다. 로딩 화면도 정상 홈 화면의 배치와 크기에 맞췄습니다.

## 저장 재시도 보호

**v20 대신 v21을 사용해 주세요.** v20 배포 검토에서 빈 patch 생략 조건에 추가 보완이 필요한
경로를 발견했습니다. 이전 저장의 서버 승인이 확인되지 않았다면 빈 diff라도 생략하지 않습니다.
네트워크 실패 후 로컬 patcher가 먼저 진행한 상태를 저장 완료로 취급하지 않으며, 기존 서버
검증·충돌 처리·전체 쓰기 복구를 유지합니다. 아래 캐시·UI 개선도 모두 포함합니다.

## 저장·캐시 동기화

- 실제 본문 patch/full save 승인 뒤 첫 화면용 사본을 1.5초 debounce로 갱신합니다. 연속 저장은 합치며 초기 UI 표시를 기다리게 하지 않습니다.
- 백그라운드 읽기는 현재 편집 상태나 편집용 ETag를 바꾸지 않습니다. 다른 기기의 최신 사본을 캐시에 받더라도 그 기기의 변경을 덮어쓸 권한으로 사용하지 않습니다.
- 늦게 끝난 과거 읽기가 더 최근 읽기의 사본을 덮어쓰지 않도록 읽기 세대를 확인합니다.
- 캐시 갱신용 읽기만 승인된 메모리 뷰를 사용할 수 있습니다. 일반 읽기의 디스크 flush는 유지하고, 다음 접속은 항상 인증·revision/ETag 검사를 거칩니다. 캐시를 내구성 있는 원본으로 취급하지 않습니다.
- 서버가 patch ETag를 만들 때 인코딩한 버퍼를 전송 스냅샷으로 재사용하여 같은 DB를 다시 인코딩하는 비용을 줄입니다.
- 서버 승인이 확인된 기준에서 내용이 동일한 빈 patch만 생략합니다. 저장 실패 뒤에는 빈 diff도 서버 검증을 거치며, 실제 채팅 저장은 기존 경로로 먼저 승인받습니다.
- 사본 저장은 실패 시 한 번 재시도하며 결과·오류 종류를 기록합니다. 실패가 대화 저장을 막거나 캐시를 삭제하지 않습니다.
- 마지막 40개 동기화 진단만 메모리에 보관합니다. 저장의 root 필드 이름·작업 수·확인값·캐시 성공/실패를 기록하고 대화 내용·API 키·요청 본문·캐릭터 ID는 기록하지 않습니다.

플러그인이 실제로 매번 값을 바꾸는 동작을 임의로 차단하지 않습니다. 따라서 실제 자동 수정에 필요한
백그라운드 동기화는 남을 수 있으며, 모든 저장 요청이나 실제 변경을 제거하는 버전은 아닙니다.

## 새로고침 경고

기존 무조건 `beforeunload` 경고를 조건부로 바꿨습니다. 쉬고 있는 홈 화면은 새로고침할 수 있습니다.
미저장 DB 변경·저장 중·플러그인 저장 및 실패한 동기 쓰기·메시지 입력/첨부·생성 중·열린 편집창은 보호합니다.
같은 값의 플러그인 동기 쓰기가 실패한 경우 다시 시도할 수 있도록 실패 상태도 구분합니다.
선택적인 캐시 갱신 때문에 이탈 경고를 띄우지는 않습니다.

## 로딩 화면

- 첫 HTML·앱 내부 로딩 화면이 같은 템플릿과 작은 표현 함수를 사용합니다.
- 정상 화면의 테마 색·글꼴 종류·사이드바 크기·둥근 아이콘·모바일 GUI 설정을 로컬에 기억해 다음 접속의 첫 화면에 반영합니다. 캐릭터 이름·대화·키는 이 설정에 저장하지 않습니다.
- 실제 UI의 1024/1025px 사이드바 경계·홈 최대 폭·카드·아이콘을 맞추고, 모바일 검색창·행 높이·하단 메뉴 크기를 맞췄습니다.
- 한국어 공용 라벨도 캐릭터 목록 인증 응답을 기다리지 않습니다. 이미지는 기존 인증·로딩 경로를 유지하며 별도의 외부 이미지·폰트·Realm 요청을 추가하지 않습니다.

최초 방문이나 사용자 임의 CSS·외부 폰트·조건부 배너까지 동일한 모습을 미리 복제하는 것은 아닙니다.

## 검증·테스트

저장 후 사본 갱신의 coalescing·읽기 순서·다른 기기 ETag 보호·캐시 재시도, 일반 읽기의 flush 유지와
캐시 읽기 후 revision 재검증, 조건부 이탈 보호, 플러그인 실패 후 동일 값 재시도를 검사했습니다.
PC·모바일에서 첫 화면과 정상 화면의 주요 좌표·크기를 비교했습니다.

- 앱 1,868개 통과, 3개 건너뜀.
- 서버 283개·호환성 154개 통과, 호환성 6개 건너뜀.
- 타입 오류 0개, 기존 접근성 경고 4개. 프로덕션 빌드 성공.
- 실제 브라우저에서 저장 요청 4회의 통신 실패를 주입했습니다. 보관한 v20 빌드는 값이 서버에 도달하지 않는 문제를 재현했고, v21은 서버 검증·복구를 거쳐 최종 값이 저장됐습니다.
- 실제 빌드에서 PC·모바일·최초 로그인 전 이름 비노출·늦은 목록 인계·전체 SHA-256 delta 검증·미전송 초안 보호를 확인했고, 확인한 경로의 런타임 예외는 없었습니다.
- 약 11.44MB 합성 DB의 실제 빌드·Node 서버·Chromium 시험에서 시작마다 설정을 바꾸는 플러그인이 있어도 저장 후 캐시가 따라잡고, 다음 세 번의 부팅은 delta 적용 없이 진행됐습니다. 로컬 시험이며 Oracle·Android 시간 보장은 아닙니다.
- 실제 브라우저의 캐시 할당량 실패를 진단에 기록하고, 복구 뒤 반복 동기화가 멈추는 것을 확인했습니다. 추가 진단의 정상 상태 세 번은 모두 최신 사본으로 확인됐습니다.

Linux x64 포터블은 기존 커스텀 업데이트로 적용할 수 있습니다. 설치 경로·HTTPS·자동 실행 설정은 유지합니다.

기존 속도 측정 코드는 그대로 사용할 수 있습니다. 추가 원인 추적은
[통합 동기화 진단 코드](../ko/diagnostics/check-db-sync.browser.js)를 사용해 주세요.
v2는 저장 요청 시간과 `동기화추적`을 추가합니다. 화면 표시 후 약 10초 뒤 실행하고,
캐시를 지우지 않은 새로고침도 비교하면 `사본최신`과 `cache-write-ok`를 확인할 수 있습니다.
