# PocketRisu DataLite 18 — 변경분 계산 단축과 로딩 화면 통일

HTTPS 브라우저의 DB 변경분 확인·적용 계산을 줄이고, 처음 보이는 화면과 정상 화면의 배치를 맞췄습니다.

## 변경

- manifest의 SHA-256을 WebCrypto로 계산합니다. 동시에 최대 64개를 처리하며 HTTP·지원 불가·실패 시 기존 JS 해시로 복구합니다.
- 변경분 적용 시 요청에 사용한 manifest의 조각 길이를 재사용합니다. 전체 SHA-256·패킷 길이·범위 검증과 실패 시 전체 읽기 복구는 유지합니다.
- 첫 HTML·빈 로딩 화면·인증된 이름 미리보기가 같은 HTML 틀과 인라인 CSS를 사용합니다.
- PC는 메뉴 레일·최근 대화·홈 배치를, 모바일은 검색 헤더·캐릭터 관리 목록·하단 메뉴 공간을 유지합니다.
  사진·채팅 개수는 자리 표시자로 두고 인증된 이름만 먼저 표시합니다.
- 로딩 화면을 위해 외부 CSS·폰트·이미지·Realm 목록 요청을 추가하지 않습니다. 로딩 중 메뉴는 표시용이며 저장/편집 동작을 시작하지 않습니다.
- 인증·목록·읽기 응답에 `event-loop-recent-max`를 추가합니다. 최근 약 5초의 서버 이벤트 루프 지연 문맥이며 요청 단계 시간과 더하지 않습니다.

저장·백업·delta 형식과 인증·세션·가져오기 차단은 유지합니다. HTTPS 도구와 설치 경로도 유지합니다.
사용자 설정에 따른 모든 화면 변형의 사전 복원을 보장하지 않으며, 간헐적인 초기 요청 대기의 원인이 해결됐다고 확정한 버전은 아닙니다.

## 검증

- 앱 1,845개·서버 282개·호환성 154개 통과. 앱 3개·호환성 6개 건너뜀.
- 타입 오류 0개, 기존 접근성 경고 4개.
- 개발 서버·Chromium의 약 12MiB 합성 데이터: manifest 약 136–151 → 29–32ms, 변경분 적용 약 128–129 → 17–19ms.
  두 경로의 manifest·복원 결과가 일치했습니다. 로컬 합성 시험이며 실제 Android의 개선율을 보장하지 않습니다.
- PC/모바일에서 첫 HTML과 마운트 후 미리보기의 주요 좌표가 일치하고, 편집 제어·외부 스타일시트·미디어가 추가되지 않음을 확인했습니다.

- 프로덕션 빌드·실제 Node 서버·Chromium에서도 PC 설정 열기/닫기·모바일·첫 로그인 전 이름 비노출·마운트 후 늦은 목록 인계를 확인했습니다. 런타임 예외는 없었습니다.
- 약 11.44MB DB의 실제 NodeStorage 변경분 경로에서 네이티브 digest 호출과 전체 SHA-256 검증을 확인했습니다.
  로컬 측정의 manifest는 30ms, 변경분 적용은 18ms였습니다. 인증 대기 중에도 목록이 먼저 표시됐습니다.

## 업데이트·측정

Linux x64 포터블을 제공합니다. 기존 커스텀 업데이트 기능으로 적용하면 되며 Oracle 서버에서 직접 빌드할 필요가 없습니다.
기존 통합 콘솔 코드를 그대로 사용해 첫 접속·새로고침·채팅 저장 후 새로고침을 비교해 주세요.
`database-delta-manifest`, `database-delta-apply`, `navigation-to-list-frame`, `navigation-to-ui-frame`을 확인하면 됩니다.
`event-loop-recent-max`는 최근 서버 지연의 참고값이며 해당 요청의 총 시간이나 다른 단계에 합산하지 않습니다.
