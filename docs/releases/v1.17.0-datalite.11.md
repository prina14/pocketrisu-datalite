# PocketRisu DataLite 11 — delta 계산·화면 진입 준비 최적화

v10 이후 실측에서 가장 컸던 delta 생성과 데이터 준비 이후의 저장 기준 집계를 개선했습니다.
저장 형식·플러그인 API·인증·기기 전환 규칙과 무결성 검증은 유지합니다.

## 변경

- 서버와 브라우저가 공유하는 조각 경계 계산을 정수 연산으로 처리하고, 경계가 생길 수 없는 앞부분의 불필요한 연산과 매 바이트의 크기 분기를 줄였습니다.
- 조각 시작·길이·manifest·delta 패킷은 v10과 동일합니다. 기존 캐시나 구버전 클라이언트도 같은 데이터를 복원하며 SHA-256 검증을 유지합니다.
- 저장 동기화 기준을 준비할 때 큰 JSON 문자열의 UTF-8 크기를 내장 인코더와 재사용 64 KiB 버퍼로 집계합니다. 전체 문자열 크기의 바이트 배열은 만들지 않으며, 작은 문자열·구형 브라우저·API 실패 시 기존 계산으로 돌아갑니다.
- 필수 저장 준비나 플러그인을 뒤로 미루지 않습니다. 데이터 준비 후 초기화와 UI 렌더링 기회를 따로 측정할 수 있도록 `save-baseline-init`, `post-data-init`, `navigation-to-ui-frame`을 추가했습니다.

## 확인한 효과

- 약 16 MB 합성 DB의 로컬 HTTP 시험에서 서버 delta 생성 중앙값 **115.72 → 50.88ms**, HTTP 전체 응답 **207.93 → 154.08ms**. 요청·응답 본문 바이트와 복원 내용은 동일했습니다.
- 실제 Chromium에서 16 MiB 조각 경계 계산 중앙값 **79.50 → 13.80ms**, 조각 1,708개의 시작·길이 일치.
- 로컬 문자열 집계 단독 시험은 16 MiB ASCII **36.60 → 0.70ms**, 한글·이모지 혼합 UTF-8 30 MiB **35.38 → 29.72ms**였습니다.
- 위 수치는 합성 데이터의 특정 단계 시험입니다. 실제 Oracle·Android 로딩 전체나 사용자가 측정한 406ms·2.24초의 개선율을 보장하지 않습니다.

## 업데이트·측정

앱 **1,821개**, 서버 **251개**, 호환성 **154개** 통과. 앱 3개·호환성 6개 건너뜀.
타입 오류 0개, 기존 접근성 경고 4개입니다. 프로덕션 빌드와 실제 Node 서버·Chromium에서
PC 첫 로그인·모바일 재접속, 큰 DB의 delta 복원·설정 열기/닫기·새 측정 항목과 캐시 저장 순서를
확인했고 런타임 예외는 없었습니다. 합성 테스트 DB와 외부 인터넷 요청을 차단한 환경의 검사입니다.

Linux x64 포터블과 SHA-256 파일을 제공합니다. 설치 서버에서 프런트엔드 빌드가 필요 없으며
기존 설치 경로·자동실행 설정과 `save/`·`backups/`를 유지할 수 있습니다.

기존 부팅 측정 명령에서 `navigation-to-ui-frame`을 확인하면 데이터 준비 종료와 UI 프레임 준비를
구분할 수 있습니다. 물리적인 화면 페인트나 모든 네트워크 작업 완료의 보장값은 아닙니다.
