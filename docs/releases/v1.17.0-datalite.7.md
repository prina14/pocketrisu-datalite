# PocketRisu DataLite 7 — 대화 우선 초기 로딩 최적화

PocketRisu 기반 데이터 절약 커스텀 버전입니다. `v1.17.0-datalite.6`에서 업데이트할 수 있습니다.

## 초기 UI 및 외부 목록

- 메인 페이지의 캐시 사용량 카드와 본문 집계 코드를 제거했습니다. 실제 DB·플러그인·채팅 캐시는 유지합니다.
- `hideRealm`이 없는 DB와 새 테마는 Recently Uploaded를 접고 시작합니다. 기존 `hideRealm: false`는 보존합니다.
- 모바일 기본 진입 탭을 캐릭터 목록으로 변경했습니다. Realm 탭은 명시적으로 열 때 로드합니다.
- Realm 추천·전체 목록·상세, 빠른 설정, 프리셋·모델·테마·페르소나·메모리 관리, 북마크·에셋 뷰어·팝업 편집기 등을 동적 import로 분리했습니다. 이전 소스 작업의 설정·모델 프로필·HypaV3 지연 로딩도 포함합니다.
- 지연 import 중 취소·단축키 닫기에서 선택 콜백을 정리하고 늦게 끝난 import가 창을 다시 표시하지 않도록 처리했습니다.
- Realm 약관·카드 직접 열기·Get More·뒤로가기를 유지하고 추천 목록 실패 시 재시도를 제공합니다.
- 캐릭터 목록의 이미지에 native lazy loading과 비동기 디코딩을 적용했습니다. 원본과 대화 이미지의 형식은 바꾸지 않았습니다.
- Wasmoon은 실제 Lua 초기화에서, source-map은 오류 상세 분석에서 로딩합니다. Lua 초기화 공유·JSON helper 대기·mutex와 원본 오류 fallback을 유지합니다.

## 저장소 및 서버

- 플러그인 preload의 IndexedDB 쓰기를 최대 32개 또는 1 MiB 배치로 처리합니다. 메타데이터 전체 스캔도 배치마다 한 번 수행하며 큰 단일 값은 별도 처리합니다.
- 기존 512 MiB 캐시 상한과 인증·validator 검증을 유지합니다. 배치 실패는 원자적으로 취소하며 중단된 스트림은 검증 완료한 행만 보관합니다.
- DB metadata-only revision probe가 대기 중인 전체 DB 저장을 강제하지 않도록 했습니다. pending patch는 메모리 revision으로 감지하고 실제 본문 읽기는 기존처럼 먼저 저장합니다.
- 서버 크기 조회는 raw BLOB을 Node로 복사하지 않고 SQLite LENGTH와 청크 marker 검사로 처리합니다.
- 백업 알림 설정 읽기를 플러그인 초기화와 겹치고, 저장소 지속성 요청·앱 업데이트 확인·공개 통계는 첫 렌더링 기회 뒤에 시작합니다. 백업 확인 절차는 유지합니다.
- `pocketrisu:startup:*` Performance 측정을 추가했습니다. 진단용 UI·저장소 집계·외부 전송은 없습니다.

활성 플러그인, V2 동기 저장소 preload, 모델 등록, 형식 이관, 저장 감시와 작업 복구의 준비 순서는 유지합니다. 서버 저장·백업 형식과 single-writer 정책은 변경하지 않았습니다.

## 검증 및 측정 범위

- 로컬 앱 테스트 1,758개, 서버 테스트 241개, 호환성 테스트 153개 통과. 타입 오류 0개이며 기존 접근성 경고 4개가 남습니다.
- 프로덕션 빌드 성공. 실제 Node 서버·임시 DB·Chromium에서 PC/모바일 부팅, 인증·재접속, 설정 열기·닫기와 설정 청크의 지연 요청을 확인했습니다.
- 별도 Chromium Realm UI 검증에서 기본 접힘·모바일 초기 목록의 Realm 요청 0회, 명시적 열기, 약관, 카드 표시·뒤로가기를 확인했습니다. 이 검증은 모의 API를 사용했습니다.
- 작은 플러그인 키 100개 테스트: 쓰기 트랜잭션과 metadata scan 각각 100회 → 4회, 읽은 metadata 행 5,050개 → 292개.
- 추가 UI 분리 단계의 초기 정적 소스 의존 경로 418개 → 326개. 이는 번들 전송량이나 실제 Android 속도 수치가 아닙니다.

사용자의 실제 Android·플러그인 구성에서 로딩 시간은 아직 실측하지 않았습니다. 선택 화면의 첫 열기에는 코드 로딩이 생기며, 최초 다운로드·DB 디코딩·V2 전체 메모리 준비 비용은 남습니다.

## Linux x64 업데이트

Oracle Ubuntu x86_64용 포터블과 SHA-256 파일을 제공합니다. 서버에서 프런트엔드를 빌드할 필요가 없습니다.
기존 설치 경로·자동실행 설정과 `save/`·`backups/`를 유지하세요. `RisuAI-NodeOnly-` 파일은 구형 자동 업데이트 호환용 동일 패키지입니다.
