# PocketRisu DataLite 10 — delta 응답·초기 요청 최적화

`v1.17.0-datalite.9` 이후 실측에서 가장 길었던 서버 delta 응답과 인증·초기 상태 준비 경로를 개선했습니다.
`load-data` 안에 `database-read`, 그 안에 `database-server-read`가 포함되므로 이 시간들을 별도 작업처럼 합산하지 않습니다.

## 서버 delta 응답

- 차이본과 전체본의 gzip 크기를 비교할 때, 전체본의 압축 출력이 차이본보다 커지는 순간 비교를 끝냅니다. 작은 차이본을 보내려고 큰 DB 전체를 끝까지 압축하던 비용을 줄였습니다.
- 압축은 비동기로 수행하고, 전체본은 한 번에 64 KiB씩 처리합니다. 비교용 전체 gzip 결과를 메모리에 보관하거나 큰 DB 사본 캐시를 추가하지 않습니다.
- 전체본이 더 작거나 같은 경우에는 끝까지 확인해 기존 선택 규칙을 유지합니다. delta 형식·SHA-256 복원 검증과 최종 응답 압축 방식도 유지합니다.
- 동일한 약 5.6 MB 합성 DB의 로컬 HTTP 시험에서 응답 중앙값은 166.26ms → 61.77ms, 압축 비교는 111.67ms → 5.70ms였습니다. 응답 본문은 양쪽 모두 4,309 B로 같고 복원 내용도 일치했습니다. 사용자 Oracle 서버·Android의 개선율을 보장하는 수치는 아닙니다.

## 초기 요청 통합

- 인증이 유지된 부팅에서는 인증 확인·세션 준비·가져오기 상태·백업 설정의 초기 요청을 4개에서 1개로 합칩니다.
- 기존 JWT/HttpOnly 쿠키 인증이 성공해야 통합 응답을 보냅니다. 진행 중인 승인된 저장이 끝난 뒤 기존 세션 등록을 수행하며, 다른 기기의 쓰기 잠금을 임의로 가져오지 않습니다.
- 가져오기 차단 상태를 확인하기 전 DB 로딩을 시작하지 않습니다. 이후 상태 폴링은 서버를 새로 조회하고, 백업 알림 표시 시점도 유지합니다.
- 비밀번호 입력·설정이 필요한 접속, 구버전 서버·클라이언트 조합과 불완전한 통합 응답은 기존 개별 조회 경로를 사용합니다. 최초 연결이나 서버 쓰기 대기 시간 자체가 없어지는 변경은 아닙니다.

## 검증과 측정

- 앱 **1,809개**, 서버 **247개**, 호환성 **154개** 통과. 앱 3개·호환성 6개 건너뜀. 타입 오류 0개, 기존 접근성 경고 4개.
- 실제 서버에서 delta 복원·압축 선택·revision·인증과 쿠키, 가져오기 중 차단, 장시간 저장 중 부팅 대기와 기존 잠금 동작을 검증했습니다.
- 실제 Chromium과 소스 모듈을 연결한 시험에서 통합 요청 1회·구버전 방식 4회, 백업 설정과 최신 상태 재조회가 유지되는 것을 확인했습니다.
- v10 프로덕션 빌드도 성공했습니다. 실제 Node 서버·Chromium에서 PC 첫 로그인, 모바일 재접속의 통합 초기 요청·큰 DB delta 복원, 설정 열기/닫기와 로컬 수식 CSS·폰트를 확인했고 런타임 예외는 없었습니다. 합성 테스트 DB를 사용하고 외부 인터넷 리소스는 차단한 검사입니다.
- 서버 `Server-Timing`의 `read-*`, `boot-auth`, `boot-session`, `boot-status`로 서버 계산과 클라이언트의 대기를 구분할 수 있습니다. 추가 UI·폴링·진단 데이터 업로드는 없습니다.
- GitHub Release는 앱·서버 검사와 프로덕션 빌드, Linux x64 포터블 조립·기동 확인 후 공개합니다.

## 업데이트

Oracle Ubuntu x86_64용 포터블을 제공합니다. 기존 설치 경로·자동실행 설정과 `save/`·`backups/`를 유지하며,
설치 서버에서 프런트엔드를 빌드할 필요가 없습니다. `RisuAI-NodeOnly-`는 구형 업데이트 호환용 동일 패키지입니다.
