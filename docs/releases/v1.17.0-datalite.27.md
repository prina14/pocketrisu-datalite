# DataLite 27 — 포터블 업데이트의 백업 보존 수정

DataLite 26의 실제 업데이트 후 검증에서 포터블 기동 시험이 만든 빈 `backups/` 폴더가 배포 파일에 포함되고, 기존 업데이트 코드의 파일 설치 단계가 해당 폴더를 기존 서버 백업 위에 덮어쓰는 문제를 확인했습니다. 실제 업데이트 전 만든 백업이 업데이트 후 목록에 남지 않는 현상으로 발견했습니다.

- 포터블 기동 시험 뒤 `save/`와 함께 `backups/`도 제거하고, 둘 중 하나라도 남으면 패키징을 실패시킵니다. 기존 버전의 업데이트 코드를 사용하는 서버도 빈 백업 폴더를 받지 않습니다.
- 웹 업데이트와 CLI 업데이트 모두 보호 대상 폴더를 기존 파일 이동 단계뿐 아니라 새 파일 설치 단계에서도 보존합니다. 기본 백업·사용자 지정 백업 폴더·저장 데이터·환경 설정을 같은 정책으로 보호합니다.
- 실제 두 설치 경로의 파일 교체 코드를 임시 폴더에서 실행하는 회귀 테스트를 추가했습니다. 빈 백업 폴더가 포함된 패키지를 적용해도 기존 기본·사용자 지정 백업과 저장 데이터·환경 설정이 보존되고 앱 파일은 교체되는지 확인합니다.

이 수정이 이미 덮어써진 백업 파일을 복구하지는 않습니다. 현재 DB와 플러그인 데이터 형식은 변경하지 않습니다. DataLite 26의 로딩 화면 인계 개선을 포함합니다.

로컬 백업 보존 회귀 테스트 2개 통과. GitHub Actions에서 전체 검사·빌드·포터블 기동 시험을 다시 수행한 뒤 게시합니다.
