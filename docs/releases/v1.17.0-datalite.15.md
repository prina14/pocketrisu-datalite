# PocketRisu DataLite 15 — 작은 캐릭터 목록 선행 표시·서버 응답 재사용

전체 DB를 기다리는 동안 인증된 실제 캐릭터 이름을 먼저 보여주고, 최신 DB의 바이너리·gzip·
delta 조각 정보를 서버에서 재사용해 접속마다 반복하던 계산을 줄였습니다.

## 변경

- 새 `/api/startup-preview`가 이름 최대 40개와 전체 개수만 담은 작은 목록을 제공합니다.
  유효한 세션이 있으면 앱 본체 로딩과 병렬로 표시하고, 첫 로그인은 인증 후 전체 DB와 병렬로 읽습니다.
- 이름은 읽기 전용입니다. 인증·가져오기 차단 확인을 통과해야 표시하고 편집·전송은 기존 초기화 후 활성화합니다.
- 최신 DB 바이너리·ETag·gzip 결과를 서버에서 재사용하며, 저장 큐 작업 뒤에는 변경된 view를 사전 준비합니다.
- 조각 경계·해시·전체 SHA-256을 재사용합니다. 기존과 동일한 delta 패킷과 무결성 검증을 유지합니다.
- 현재 RAM 여유를 활용하도록 완성본 캐시 상한을 기본 64 MiB로 설정했습니다. 최신 한 버전만 보관합니다.
- `navigation-to-list-frame`, `startup-preview-read`, 서버의 `x-read-snapshot`, `read-compress` 측정을 추가했습니다.

## 확인한 효과

약 12.65MB 합성 DB의 로컬 HTTP 5회 중앙값에서 준비된 전체 응답은 **163.83 → 6.35ms**,
delta 응답은 **81.84 → 4.20ms**였습니다. 전체·delta의 gzip 본문 크기와 복원 내용은 동일했습니다.

실제 프로덕션 빌드·Node 서버·Chromium에서 DB 응답을 5초 늦춘 시험에서도 목록은 **111ms**에,
전체 DB 적용 후 미리보기는 **5,581ms**에 기록됐습니다. PC·모바일·첫 로그인·설정 전환에서
런타임 예외는 없었습니다. 로컬 합성 시험이며 실제 Oracle·Android 개선율이나 1초 이내를 보장하지 않습니다.

앱 1,840개·서버 273개·호환성 154개 통과. 타입 오류 0개, 기존 접근성 경고 4개입니다.
저장·백업 형식, 플러그인 API, 세션 권한과 기존 자동 업데이트·HTTPS 복구 도구를 유지합니다.

## 업데이트·측정

Linux x64 포터블을 제공하며 기존 커스텀 업데이트로 적용합니다. 기존 측정 코드를 그대로 사용하고
`navigation-to-list-frame`을 확인하면 실제 이름이 먼저 표시된 시점을 볼 수 있습니다.
전체 DB 전송은 여전히 진행되므로 첫 다운로드의 총 바이트나 전체 준비 시간을 같은 비율로 줄이는 변경은 아닙니다.
