# PocketRisu DataLite 13 — 기본 화면을 먼저 표시하는 시작 구조

전체 앱·데이터 준비가 끝나기 전에도 PocketRisu 헤더와 캐릭터 영역의 기본 레이아웃을 표시합니다.
전체 처리를 1초 안에 끝내는 변경이 아니라, 먼저 화면을 보여주고 필요한 준비를 이어가는 변경입니다.

## 변경

- 첫 화면을 HTML과 작은 inline CSS로 구성해 앱 JS·전체 CSS·폰트·이미지·DB 응답을 기다리지 않습니다.
- 가벼운 main 진입점은 화면 렌더링 기회 이후 앱 본체와 CSS를 동적 로드합니다. 숨김·지연된 탭에도 시작 복귀 경로를 제공합니다.
- 앱이 마운트된 뒤에도 같은 기본 레이아웃을 유지하고, 인증·가져오기 차단 확인과 최신 DB 적용 후 실제 캐릭터 이름을 표시합니다. 채팅·편집은 기존 초기화 완료 후 활성화합니다.
- 초기 앱/CSS 파일 로딩 실패 시 기본 화면에 새로고침 버튼을 제공합니다.
- 활성 V2 플러그인의 공유 저장소 사전 읽기를 미리보기 프레임 대기와 겹쳐 시작합니다. V2 실행 전 전체 값 준비와 실패 시 실행 차단은 유지합니다.
- `navigation-to-shell-frame`과 인증 요청·비밀번호 입력 대기·플러그인 준비 세부 측정을 추가했습니다. 기존 측정 명령을 그대로 사용할 수 있습니다.

## 확인과 측정

앱 검사 **1,833개 통과**, 3개 건너뜀. 타입 오류 0개, 기존 접근성 경고 4개입니다.
앱 파일 요청을 멈춘 로컬 Chromium 시험에서도 첫 콘텐츠가 PC 80ms·모바일 화면 크기 36ms에
표시됐으며, 파일 503 응답의 복구 버튼을 확인했습니다. 실제 Android·Oracle 접속 시간의
개선율이나 모든 환경에서 1초 이내 표시를 보장하는 수치는 아닙니다.

프로덕션 빌드와 실제 Node 서버·Chromium에서도 PC 로그인·모바일 재접속·delta 복원·
변경 없는 재접속의 304 응답·설정 열기와 닫기를 확인했고 런타임 예외는 없었습니다.
프로덕션 로컬 합성 시험의 FCP는 PC 56ms·모바일 화면 크기 40ms였습니다.

최초 기본 화면은 개인 캐릭터 정보가 없는 빈 레이아웃입니다. 실제 이름은 최신 DB 확인 후 표시합니다.
DB revision 확인·delta 복원·무결성 검증·저장 형식과 백업 형식은 유지합니다.

Linux x64 포터블과 SHA-256 파일을 제공합니다. 기존 커스텀 자동 업데이트로 적용할 수 있으며,
설치 서버에서 프런트엔드를 다시 빌드할 필요가 없습니다.
